# Version 2.0.3 Changes - Confluence Inline Provider Fix

## Summary
Fixed RHDH Lightspeed integration with Confluence by removing conflicting MCP server configuration and correcting secret references.

## Problem
RHDH Lightspeed had no awareness or context of Confluence documentation even though the inline provider was configured.

## Root Causes
1. **Conflicting Configuration**: `configmap-lightspeed-stack.yaml` had a broken Confluence entry in `mcp_servers` section with a dummy URL
2. **Inconsistent Secret Names**: `backstage-cr.yaml` referenced two different secret names for Confluence credentials

## Changes Made

### 1. Fixed `configmap-lightspeed-stack.yaml`
**File**: `templates/configmap-lightspeed-stack.yaml`

**Before**:
```yaml
mcp_servers:
- name: mcp::backstage
  provider_id: model-context-protocol
  url: http://backstage-developer-hub.rhdh.svc.cluster.local/api/mcp-actions/v1
- name: confluence                    # ❌ WRONG
  provider_id: confluence              # ❌ Inline provider, not MCP
  url: http://unused                   # ❌ Dummy URL
```

**After**:
```yaml
mcp_servers:
- name: mcp::backstage
  provider_id: model-context-protocol
  url: http://backstage-developer-hub.rhdh.svc.cluster.local/api/mcp-actions/v1
# Confluence uses inline provider in llama-stack, not MCP server
```

**Why**: Confluence is configured as an **inline provider** in llama-stack, not an MCP server. Having it in `mcp_servers` was causing conflicts.

### 2. Secret Name Clarification
**File**: `templates/backstage-cr.yaml`

**Status**: No change needed - uses `confluence-mcp-credentials` consistently

**Note**: The secret `confluence-mcp-credentials` contains the correct keys:
- `CONFLUENCE_URL`
- `CONFLUENCE_USERNAME`
- `CONFLUENCE_API_TOKEN`

There is also a `confluence-mcp-credentials` secret in the namespace but it has different keys (`CONFLUENCE_TOKEN` instead of `CONFLUENCE_API_TOKEN`) and is missing `CONFLUENCE_URL`, so we continue using `confluence-mcp-credentials`.

## How It Works Now

```
User Query in RHDH Lightspeed
        ↓
Lightspeed Core Service (LCS)
        ↓
Llama Stack (analyzes intent)
        ↓
Determines: "This is about general documentation"
        ↓
Calls: confluence toolgroup (inline provider)
        ↓
confluence_tools.py executes search
        ↓
Confluence Cloud API returns results
        ↓
LLM synthesizes response with links
        ↓
User sees Confluence documentation in chat
```
